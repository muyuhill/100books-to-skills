# 《搞定》— 五步清空大脑，只做该做的事

戴维·艾伦（David Allen）的 GTD（Getting Things Done）不是一套「优先级排序」的理论，而是一套**把大脑里的杂乱导出到外部系统、让大脑只负责思考而非记忆**的工作流。核心信念：**你的大脑是用来产生想法的，不是用来存储想法的。**

---

## 一、GTD 五步工作流

```
收集 ──→ 理清 ──→ 组织 ──→ 回顾 ──→ 执行
  ↑                                    │
  └──────────── 新事项不断进入 ──────────┘
```

### 第一步：收集（Capture）

**把所有「未尽事宜」赶出大脑，放入一个外部收件箱。**

- 🎯 目标：100% 清空大脑。任何引起你注意的事情——任务、想法、承诺、灵感——一律记下来。
- 📥 收件箱可以是：纸质笔记本、手机备忘录、邮件草稿箱、语音备忘录、便签 App。
- ⚠️ 关键原则：**收件箱越少越好**，理想状态下 1-3 个。不要让收集工具分散。
- ✅ 每想到一件事，不问「重要吗？紧急吗？」，先记下来。判断留给下一步。

**你该对用户说什么：**
> 「先把所有盘旋在你脑子里的东西倒出来。不管是『给妈妈打电话』还是『写年度战略报告』，统统写进收件箱。不要在此刻判断、排序、后悔——只收集。」

---

### 第二步：理清（Clarify）

**逐条处理收件箱中的每一项，问两个问题：**

```
┌─────────────────────────────────┐
│  这是什么？                       │
│  需要采取行动吗？                  │
└─────┬───────────────────────────┘
      │
      ├── 不需要行动 ──→ 三类归宿：
      │   • 🗑️ 垃圾（删除）
      │   • 📋 将来/也许清单
      │   • 📚 参考资料（归档备查）
      │
      └── 需要行动 ──→ 继续判断：
          │
          ├── 下一步行动是什么？
          │   （具体的、物理的、可见的动作）
          │
          ├── ⏱️ 两分钟法则：两分钟内能做完？
          │   是 → 立刻做掉！
          │   否 → 进入「组织」阶段
          │
          └── 这件事属于一个更大的「项目」吗？
              是 → 把项目写进「项目清单」
              否 → 单步行动，直接进入行动清单
```

**你该对用户说什么：**
> 「从收件箱顶端开始，逐条处理，不跳过、不挑拣。每一条必须有一个『归宿』——要么做掉、要么委派、要么推迟、要么丢弃。让收件箱归零。」

---

### 第三步：组织（Organize）

**把理清后的结果放入对应的清单/容器中。GTD 的核心清单体系：**

| 清单名称 | 存放内容 | 示例 |
|---------|---------|------|
| **下一步行动清单** | 单步即可完成的动作 | 「回复张总邮件」「买猫粮」 |
| **项目清单** | 需要多步才能完成的结果 | 「装修厨房」「通过PMP考试」 |
| **等待清单** | 委派出去、等别人回复的事项 | 「等IT部门重置密码」「等客户签合同」 |
| **将来/也许清单** | 现在不做、以后可能做的想法 | 「学西班牙语」「去冰岛旅行」 |
| **日历** | 有严格时间/日期刚性的事项 | 会议、航班、截止日（不含「我希望这天做」的软性任务） |
| **参考资料** | 无需行动、但日后可能查阅的信息 | 菜单、说明书、账号列表 |

**🔥 GTD 的独到之处：情境清单（Context Lists）**

不要按「优先级」组织行动清单，而按**「你当下所处的场景」**来组织：

| 情境 | 标签示例 |
|------|---------|
| @电脑 | 需要联网才能做的事 |
| @办公室 | 只能在办公场所做的事 |
| @电话 | 需要打电话或接听的任务 |
| @家 | 回到家里才能做的事 |
| @外出 | 出门在外、跑腿类事项 |
| @任何人 | 可以在任何地方做的事 |

**为什么这样做？** 优先级是主观且流动的，而「你此刻能不能做这件事」是客观的。当你坐在电脑前时，你不需要看「@外出」清单；当你在路上时，@电脑 的任务看了只会增加焦虑。

**你该对用户说什么：**
> 「不要按重要程度 P0-P4 排列你的行动清单。按『你在哪里、你有什么工具』来切片。坐在电脑前就看 @电脑 清单，开车回家的路上扫一眼 @外出 清单。让你的情境替你过滤出此刻真正可行的任务。」

---

### 第四步：回顾（Review）

**🔥 这是 GTD 的核心引擎——每周回顾（Weekly Review）。**

没有回顾，GTD 系统会在 2-4 周内崩溃。每周回顾是你对自己承诺的「定期维护」。

**每周回顾的标准流程（约 1-2 小时）：**

1. **收集散落**：把所有便签、邮件、聊天记录、脑中杂念倒入收件箱。
2. **处理收件箱**：逐条理清，让收件箱归零。
3. **过一遍所有清单**：下一步行动、等待、项目、将来/也许——逐一审视。
4. **审视项目清单**：每个项目至少有一个「下一步行动」吗？如果没有，补上。
5. **审视日历**：过去一周未完成的事项需要重新安排吗？未来两周有需要准备的事情吗？
6. **清空大脑**：还有什么在困扰你？写下来，理清，组织。
7. **回顾「将来/也许」清单**：有没有什么现在该激活了？

**你该对用户说什么：**
> 「每周回顾是 GTD 的命脉。找一个周五下午或周日晚上，关掉通知，用 60-90 分钟把整个系统『重置到零』。这不是可选项——没有回顾的系统是死系统。」

---

### 第五步：执行（Engage）

**面对你的清单时，用四标准模型选择此刻做什么：**

```
┌─────────────────────────────────────┐
│  选择行动的四个标准（按优先级排序）： │
│                                      │
│  1. 情境（你在哪？有什么工具？）       │
│  2. 可用时间（你有多少时间？）         │
│  3. 可用精力（你现在精力充沛吗？）     │
│  4. 优先级（所有条件相同时的最终判断） │
└─────────────────────────────────────┘
```

**三种工作模式：**

| 模式 | 适用场景 | 做法 |
|------|---------|------|
| **执行预定义任务** | 正常工作时间 | 看当前情境的「下一步行动」清单，逐项推进 |
| **处理突发事件** | 有新事项插进来 | 两分钟法则快速判断：能做就做，不能做就扔进收件箱 |
| **定义工作** | 收件箱堆积、大脑混乱时 | 暂停执行，回去做「理清」和「组织」，让系统恢复清晰 |

**你该对用户说什么：**
> 「当你不知道该做什么的时候，问问自己：我在哪里？我有多少时间？我精力如何？然后打开对应情境的清单，从上往下做。信任你的系统——如果一件事不在清单上，它就不存在，你此刻不需要为它焦虑。」

## 二、核心法则速查

### 🔑 两分钟法则
> 如果一件事两分钟内能做完——**立刻做**。不要组织、不要推迟、不要写进清单。两分钟花在「整理」上比「执行」上更浪费。

### 🔑 下一步行动（Next Action）
> 对每个项目必须问：**「推进这件事的、下一个具体的、物理的、可见的行动是什么？」** 「弄一下项目 X」不是下一步行动。「打开 Excel，填好预算表的前三列」才是。

### 🔑 项目定义
> **项目 = 需要多个步骤才能完成的、你承诺达成的结果。** 任何需要 ≥2 个行动才能闭环的期望结果都是项目。项目清单是你所有「开放循环」的总索引。

### 🔑 心智如水（Mind Like Water）
> GTD 的终极状态：大脑像平静的水面，投入一颗石子（新事项），涟漪泛起，恰当反应，然后恢复平静。不积压、不焦虑、不遗忘。

### 🔑 自然式规划模型
> 面对复杂项目时，不要从「制定计划」开始，而是用大脑的自然思考顺序：
> 1. 定义目标和原则（为什么做？）
> 2. 展望结果（做成什么样？）
> 3. 头脑风暴（怎么做到？）
> 4. 组织（排序、划分子任务）
> 5. 确定下一步行动（现在马上做什么？）

## 三、与用户对话的常用句式

**当用户说「事情太多，脑子很乱」时：**
> 「来，我们先把所有事情都倒出来。不要过滤，全部写进收件箱。你现在脑子里总共飘着多少件事？10 件？50 件？先全部写下来，一条一条来。」

**当用户想按优先级排序时：**
> 「先别急着定优先级。GTD 的做法是按情境（你在哪、能做什么）来选任务，而不是按『重要程度』纠结。如果你现在在电脑前，就只看 @电脑 清单；重要性排序是最后一步才考虑的事。」

**当用户说「我没时间做每周回顾」时：**
> 「恰恰相反——正是因为没回顾，你的系统正在『暗地里』吞噬你的注意力。花一小时回顾，能省下接下来一周大量的精神内耗。试试看，周五下午四点，只做一次。」

**当用户面对一个大项目不知如何下手时：**
> 「不要想整个项目。只问你：**推进这个项目的下一个具体动作是什么？** 不用很大——打开一个文档、发一条微信、查一个数据——只要是你能在几分钟内完成的物理动作就可以。」

## 四、常见陷阱与破解

| 陷阱 | 表现 | 破解方法 |
|------|------|---------|
| 收件箱变成黑洞 | 收集了但从不处理 | 固定每天处理 1-2 次收件箱，目标是归零 |
| 清单太长不敢看 | 行动清单 200+ 条 | 把「将来/也许」真正用起来，不要把一辈子想做的事都放在行动清单 |
| 没有下一步行动 | 项目清单里写着结果，但没有可执行的下一步 | 每周回顾时强制检查：每个项目至少有一个以动词开头的下一步行动 |
| 过度收集 | 把「思考」也当成任务放收件箱 | 收件箱放「承诺」，不是「念头」。把思考结果写进项目支持材料 |
| 工具不停切换 | 每周换一个待办 App | 选一组工具，用满 3 个月再调整。工具不是问题，习惯才是 |

## 五、建议与用户一起搭建的系统

当用户想要实践 GTD 时，帮他们一步步搭建：

1. **选择一个主收件箱**（可以是苹果备忘录 / Notion / Todoist / 纸质笔记本）。
2. **一起做一次「大脑清扫」** — 把用户当下能想到的所有未尽事宜全部写出来（目标：100 条以上）。
3. **逐条理清** — 每一条问「需要行动吗？下一步行动是什么？属于哪个项目？」
4. **建立核心清单**：下一步行动（按情境标签分类）、项目清单、等待清单、将来/也许清单。
5. **在日历上固定每周回顾时间** — 这是最重要的一步，没有之一。
6. **三天后跟进**：收件箱清空了吗？清单在变短还是在变长？（变长是正常的——说明你真的在用）。
